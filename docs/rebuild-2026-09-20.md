# Review companion rebuild

JEV Gate now uses one review engine for the CLI, GitHub Action, and OpenCode adapter.
The previous design made a model score carry too much responsibility. A score could
block a correct sensitive change, while missing input or a failed review could look
successful. Version 0.2 separates findings, policy, and review health.

## Changes against the audit

| Audit problem | Implemented behavior |
| --- | --- |
| Local policy differed silently from GitHub policy. | Root configuration discovery, explicit working/base policy, and captured policy identity. |
| Patches disappeared or were silently clipped. | Unicode path decoding, bounded candidates, explicit exclusions and omissions, GitHub count reconciliation, and truncated-patch warnings. |
| Sensitive changes blocked by default. | Advisory default; sensitive findings request verification. Required gates are explicit. |
| Findings had no useful location or lifecycle. | Candidate locations, verification steps, stable identities, and local acceptance/dismissal with a reason. |
| Harness warnings were stale, lost, repeated across sessions, or never retried. | Serialized monitor; freshness checks; separate assessment/delivery records; per-session delivery; bounded retry; cancellation of owned child processes. |
| Provider failure could leave success visible. | Unavailable status, exit 2, and an updated GitHub comment when the revision remains current. Invalid policy also reports unavailable. |
| Calibration could succeed without usable answers. | Label manifest, tune/holdout split, pinned model requirement, identity records, precision/recall, and invalid evaluation on missing answers. |
| Rule identity omitted parts of the prompt. | Fingerprint of complete questions and rubrics, plus effective policy and state format version. |
| Provider requests could contain recognizable credentials. | Local detection and redaction before provider calls; located findings without credential values. |
| Integration and dependency behavior were unclear. | Bundled runtime tests, revised setup docs, npm release-age enforcement in CI, no plugin runtime SDK dependency, and the vulnerable development dependency updated. |

Additional regression checks caught two delivery bugs during implementation. Accepting a
finding now invalidates the cached assessment. A briefing that displays ten findings only
acknowledges those ten, so remaining findings can reach the next context call.

## Verified locally

- Both TypeScript projects pass typechecking.
- All 71 tests pass on both Node 26 and Node 20.20.1, including bundled CLI and Action execution.
- Runtime adapter tests cover child CLI invocation, recipient isolation, restart, and
  cancellation of an owned process and its descendant. Bun 1.3.10 loads the actual plugin
  package entrypoint. This does not constitute a complete interactive OpenCode session test.
- Installation into a private temporary prefix produces a working `jev-gate` executable.
- `npm audit` reports zero vulnerabilities in the installed dependency graph.
- Package inspection excludes private local evidence. `git diff --check` passes.

The independent Claude review attempt returned HTTP 429 before reviewing code because the
installed account had reached its weekly limit. Independent review remains unverified.

## Live evaluation and dogfooding

Six Agentum pull requests were reviewed through OpenRouter with
`typesafe/jev-1.13-20260917`. Five completed under the default budget. The largest reported
partial coverage at 64 of 99 candidates and completed under an explicit 128-call budget.
The product default remains 64. All six final reviews completed without provider errors.

Dogfooding exposed an unquoted environment credential that the original local scanner
missed. The value reached the configured provider on the first run. Redaction now covers
that assignment and quoted JSON credentials. A live forwarding check confirmed that the
captured value is absent from subsequent outgoing request bodies.

It also exposed false positives from test-quality scoring. Stronger instructions did not
resolve them. That rule is now experimental and disabled by default. Opt-in use is restricted
to recognized test-code paths. The secret rule's synthetic probe-key false positive cleared
after its exclusions were made explicit. Some compatibility findings still need judgment;
an internal helper's signature change is not sufficient evidence of a public API break.

The final labeled evaluation ran three repetitions over 21 tuning diffs and six untouched
holdout diffs. All 93 labels for enabled rules matched their expected outcomes. Two tuning
examples label only the disabled test-quality rule and do not enter default-policy metrics.
The [raw synthetic results](../samples/results/2026-09-20-openrouter-jev-1.13-20260917.json)
retain the observations and identities. This small suite does not establish production accuracy.

The real bundled CLI and adapter also passed a live provider test using a temporary Git
fixture and simulated host context. It verified credential withholding, one-time delivery,
and assessment refresh after accepting a finding. Captured Agentum source, the detailed
report, and live-run artifacts remain in the ignored `.jev-gate/dogfood/` directory.

Before treating this version as a required merge gate, expand real-change adjudication and
obtain independent review. Locations remain candidate ranges. The secret detector recognizes a limited set
of patterns. Coverage and verification instructions make those limits visible; they do
not replace investigation of callers, contracts, or runtime behavior.

## Contract changes

Results use schema 2. Consumers of the previous result format must update. The adapter
requires the CLI from this revision. The old Action options that silently skipped missing
keys or provider errors have been removed. Rubric observations are displayed in rubric
units, and `--no-gate` suppresses finding-related exit 1 while preserving error exit 2.

The bundles and source are updated locally. No release or GitHub comment was published.
